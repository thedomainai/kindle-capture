# Kindle Capture 問題分析

## 確認済みの不具合

### 1. click_window_center() がページを戻す
- **根本原因**: Kindle リーダーはタップゾーンを使用する。左半分=前ページ、右半分=次ページ、中央=ツールバー表示/非表示
- **影響**: ループ中の click_window_center() がページ逆行・ツールバー表示を引き起こす
- **対処**: click を完全に除去。キーボードのみでページ送りする

### 2. pixel_hash が PNG バイトを比較している可能性
- **根本原因**: CGImageGetDataProvider(img) は PNG 読み込み元の provider を返す場合がある
- **検証結果**: bitmap context 経由のデコードは決定論的。同一ファイルから同一ハッシュが得られる
- **対処**: bitmap context 経由でピクセルデータを取得してハッシュする

### 3. key code がプロセス外に送信される
- **根本原因**: send_page_turn() で `key code 124` が `tell process "Kindle"` の外で実行されている
- **影響**: フォーカス競合時に別アプリにキーが送られる
- **対処**: key code を `tell process "Kindle"` ブロック内で送信する

## 潜在的な不具合

### 4. レンダリング完了前のキャプチャ
- ページ遷移アニメーション中にスクリーンショットを撮ると中間フレームが保存される
- **対処**: 安定化ループ（2回連続で同一ハッシュになるまでポーリング）を導入

### 5. Kindle がカーソルを表示する場合
- ウィンドウ内にテキストカーソルがあると、ブリンクでピクセルが変化する
- **対処**: 安定化ループで吸収可能（カーソルの状態が安定するまで待つ）

### 6. ツールバーの表示状態変化
- ツールバー表示/非表示でスクリーンショットが変わるが、ページ遷移ではない
- **対処**: ツールバーが出た場合はページ内容は変化しないため、安定化後の比較で問題なし

### 7. ウィンドウ ID の変化
- Kindle がウィンドウを再生成するとIDが変わる
- **対処**: 毎ループで find_kindle_window() を呼んで更新（実装済み）

### 8. screencapture -l がウィンドウシャドウを含む
- シャドウ部分は背景の透過でキャプチャ毎に変化しうる
- **対処**: -o フラグでシャドウを除外（実装済み）

## 設計方針

### キャプチャフロー（修正後）

```
初期化:
  1. Kindle プロセス確認
  2. ウィンドウ ID 取得
  3. Kindle をアクティブ化（activate のみ。クリックしない）
  4. 初回ページをキャプチャ＆安定化ハッシュ取得
  5. テストページ送り（1回送って変化するか検証）

メインループ:
  1. ページ送り（key code 124 を Kindle プロセス内で送信）
  2. 基本待機（delay 秒）
  3. 安定化ポーリング:
     a. キャプチャ A → ハッシュ A
     b. 短い待機（0.3s）
     c. キャプチャ B → ハッシュ B
     d. A == B → 安定（レンダリング完了）
     e. A != B → 繰り返し（タイムアウトまで）
  4. 安定ハッシュを前ページと比較
  5. 異なる → 新ページとして保存
  6. 同じ → ページ送りリトライ（最大 N 回で終了判定）
```
